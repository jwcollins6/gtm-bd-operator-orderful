# Onboarding

Required for every client, before either the outbound or inbound track launches
(not outbound-first-then-retrofit-inbound-later). This is what builds the shared
company understanding both directions depend on — see
`../docs/OFFERING_SPEC.md`'s "shared foundation" section for the full rationale.

Do these in roughly this order:

1. [`company-understanding-inventory.md`](company-understanding-inventory.md) —
   customers, inbound history, existing messaging, website, differentiation.
2. [`icp-template.md`](icp-template.md) — company-level fit criteria, built from
   #1's customer/inbound findings plus recently-won-deals and the client's own
   stated understanding.
3. [`persona-template.md`](persona-template.md) — who at a fitting company,
   since different personas need different messaging.
4. [`signal-inventory-template.md`](signal-inventory-template.md) — what actually
   means "reach out now" for this business.
5. [`tech-stack-audit-template.md`](tech-stack-audit-template.md) — what they use
   today and how, which directly feeds:
6. [`storage-decision-worksheet.md`](storage-decision-worksheet.md) — where this
   client's data actually lives.

For a new or small client with thin history on any of these: note explicitly
what's missing, use whatever real material exists, and fill gaps with independent
research. Never fabricate a finding to fill a gap.
